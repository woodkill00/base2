# Complete user-journey assurance

Preserve the approved Volcano design while verifying useful user outcomes, not
merely page loading. Every routed surface must have an explicit coverage record
distinguishing fixture interactions, real-backend journeys, captured screenshots,
reviewed visual comparisons and separately authorized live evidence.

## Requirements

- R01 Track every public route, protected route family and operator surface;
  added routes require a coverage decision. Disabled profiles do not prove enabled
  functionality. Missing evidence remains pending or blocked, never passed.
- R02 Exercise registration, login/logout, verification, password recovery,
  validation, expired/reused links and session loss using disposable accounts.
- R03 Verify dashboard destinations and settings persistence, permission variants,
  enabled security controls and recovery without modifying the reusable owner.
- R04 Verify contact submission/idempotency, populated search, pagination,
  detail navigation, localized content, enabled modules and failure recovery.
- R05 Verify workspace, invitation, booking, media and operations workflows with
  synthetic data, including authorization failures and cleanup.
- R06 Verify visual states: populated, empty, loading, success, validation,
  unavailable, disabled and permission-denied. Preserve existing approved
  references. Captures alone are not comparisons; new references require review.
- R07 Cover critical browser engines, touch/keyboard, zoom, long content, RTL,
  user preferences and responsive geometry using bounded representative matrices.
- R08 Integrate regressions into standard assurance; record actionable failures
  and exact-source evidence. Do not silently skip prerequisites or accept retries
  as proof of reliability. Existing coverage floors remain unchanged.

## Acceptance scenarios

P1: A visitor can recover access, submit a form and search without silent failure,
false success or stale results. Error and retry states are actionable and styled
consistently. Disposable backend journeys prove persistence and token expiry.

P2: An authorized user completes settings and content workflows; unauthorized
users cannot obtain data or perform actions. Reload retains successful changes.

P3: Every enabled page family remains usable across representative devices and
user preferences. Missing required cases cause assurance failure, not silent pass.

## Safety and acceptance

No production account mutation, external email delivery, credentials, paid preview,
provider changes or baseline redesign is authorized by this feature. Local test
mail capture and disposable tenants are required for destructive journeys. Live
trial and reference approval remain separately gated. Completion requires every
task's actual evidence, not a promise that unknown defects cannot exist.
