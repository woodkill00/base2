# Public experience acceptance

The Feature 093 public checkpoint has zero unexplained public routes or controls. The source ledger is `specs/093-base2-foundation-hardening/experience-inventory.md`; the required complete gate binds it to the implementation.

Automated acceptance covers Chromium, Firefox, and WebKit on desktop plus Chromium and WebKit mobile/touch profiles. It exercises local-only networking, responsive overflow, keyboard focus, touch navigation, locale selection/fallback, and degraded-network states without retries. The deterministic visual matrix covers desktop, tablet, and mobile themes, reduced motion, WCAG checks, focus indication, and a negative accessibility control.

Manual review confirms logical heading order, meaningful control labels, readable zoom/reflow, visible focus, reduced motion, consistent branded states, and no unexplained action. Real screen-reader and physical-device observations are retained for the final all-module T111 checkpoint; browser automation is not described as a substitute.

Both fixture brands must compile under hard JavaScript-chunk, stylesheet, and total emitted-output budgets. The build itself rejects an over-budget artifact. Transactional email, analytics, search, and contact behavior remain manifest-gated and disabled where unsupported. Live providers, production certificates, payments, publication, deployment, and any provider activation remains prohibited without their separately approved activation boundaries.
