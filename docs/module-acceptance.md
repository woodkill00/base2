# Module acceptance

The required module checkpoint loads every declarative pack through the public registry and completes install, disable, enable, migration preview, upgrade, and export in an owner-only temporary lifecycle store. It also rejects route conflicts, emits a deterministic route inventory digest, proves no state is retained, and reports zero credential reads and network calls.

The complete gate binds that checkpoint to the hermetic visual harness, accessibility matrix, public experience/performance checkpoint, browser compatibility matrix, pack-specific suites, and coverage policy. Destructive removal, real providers, credentials, publication, and deployment are not granted by module acceptance.
